# 인계 기록

다음 세션은 이 기록만 보고 작업을 이어받는다. 이번 대화를 모르는 사람이 읽어도 바로 시작할 수 있게 쓴다.

1. 이번 세션에서 한 일을 정리한다. 변경한 파일, 검증 결과(통과/실패/미검증), 남은 문제를 포함한다.
2. `.harness/state/progress.md` 를 갱신한다.
   - 완료한 체크리스트 항목을 체크하고, "완료 로그" 맨 위에 `- YYYY-MM-DD: 요약 (주요 파일)` 을 추가한다.
   - "다음 할 일"은 바로 착수할 수 있을 만큼 구체적으로 쓴다. 나쁜 예: "로그인 마무리". 좋은 예: "`auth/session.ts` 의 토큰 만료 처리 — 만료 시 refresh 호출, 테스트 `session.test.ts` 에 추가".
   - 막힌 것은 시도한 방법과 실패 이유를 함께 "진행 중 / 막힌 것"에 적는다. 같은 시도를 반복하지 않기 위해서다.
   - 완료 로그가 길어지면 (대략 30줄 이상) 오래된 항목을 한 줄 요약으로 합친다. 이 파일은 매 세션 로드된다.
3. 이번에 내린 중요한 결정은 `.harness/state/decisions.md` 에 추가한다.
4. 작업 중에 `.harness/context/` 문서가 실제 코드와 달라졌다면 함께 고친다.
5. 같은 지적이나 실패가 이번 세션에서 두 번 이상 반복됐다면 `/harness-evolve` 를 제안한다.
6. 갱신한 내용을 사용자에게 3~5줄로 요약한다.
