# 계획 수립

계획을 파일에 남기는 이유는 세션이 바뀌거나 컨텍스트가 요약되어도 다음 세션이 같은 계획을 이어받게 하기 위해서다.

## 0. 진행 중인 계획 확인
`.harness/state/progress.md` 의 "현재 목표"를 확인한다.
- 비어 있거나 완료됨: 새로 계획한다 (1단계부터).
- 같은 목표가 진행 중이고 수정 요청임: 기존 계획과 피드백을 planner에게 함께 넘겨 바뀌는 부분만 고친다.
- 다른 목표가 진행 중: 기존 목표를 대체할지, 뒤로 미룰지 사용자에게 묻는다. 묻지 않고 덮어쓰면 진행 기록이 사라진다.

## 1. 계획 받기
- 영향 파일이 3개 이상이거나 낯선 영역이면 `harness-planner` 에 작업 설명을 넘긴다. 탐색 결과로 메인 컨텍스트를 채우지 않기 위해서다.
- 그보다 작으면 직접 계획하되 planner와 같은 형식을 쓴다.
- `.harness/context/domain.md` 의 "루프 연결 — 계획"에서 이번 작업에 해당하는 조건을 찾는다. 해당하는 도메인 팀 에이전트(`team-*`)가 있으면 그 에이전트에게 맡긴다. planner 결과가 필요한 일이면 planner 다음에, 독립적인 일이면 한 메시지에서 병렬로 맡긴다. 조건에 해당하지 않으면 부르지 않는다.

## 2. 확인
- 목표, 단계, 영향 파일, 위험 요소를 사용자에게 요약해서 보여준다.
- "확인 필요" 항목이 있으면 진행하기 전에 묻는다.
- "문서 불일치"가 있으면 `.harness/context/` 문서를 실제 코드에 맞게 고친다.

## 3. 기록
- `progress.md`: "현재 목표"에 목표와 완료 조건을, "다음 할 일"에 단계를 체크리스트로 적는다. 단계마다 검증 방법을 함께 적는다.
- 대안이 있었던 설계 선택은 `.harness/state/decisions.md` 에 맥락·결정·대안 형식으로 추가한다.
